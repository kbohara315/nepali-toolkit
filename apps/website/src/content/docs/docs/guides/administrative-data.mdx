Use codes as stored identifiers and names as display labels. Names can repeat or use source-specific spellings; a name match alone is not a unique address.

## Populate cascading selectors

<HairlineFigure name="address-cabinet" title="Nested Nepal address trays" description="Move from the outer tray to reveal each level of a Nepal address." guideHref="/docs/guides/administrative-data/#populate-cascading-selectors" guideLabel="Cascading selector guide" referenceHref="/docs/reference/admin/" referenceLabel="Admin API reference" />

```ts
import { getProvinces } from 'nepali-toolkit/admin/provinces';
import { getDistricts } from 'nepali-toolkit/admin/districts';
import { getPalikas, getPalikaWards } from 'nepali-toolkit/admin/palikas';

const provinces = getProvinces();
const bagmatiDistricts = getDistricts('3');
const kathmanduPalikas = getPalikas('306');
const wards = getPalikaWards('30608'); // 1 through 32
```

Reset district, palika, and ward selections when their parent changes. Pass ASCII string codes exactly; lookups do not normalize localized digits. Display `nameNe` or `nameEn` without rewriting the source spelling.

## Validate membership and parent consistency

```ts
import { getHierarchy } from 'nepali-toolkit/admin/hierarchy';
import { isValidWard } from 'nepali-toolkit/admin/validate';

const selected = { province: '3', district: '306', palika: '30608', ward: 12 };
const path = getHierarchy(selected.palika);
const valid = path !== undefined
  && path.province.code === selected.province
  && path.district.code === selected.district
  && isValidWard(selected.palika, selected.ward);
valid; // true
```

Checking each code separately does not validate their relationship. Derive the parent records from the palika and compare submitted values, or persist only the palika plus ward when that fits your data model. Ward validity is a numeric range check, not a boundary/coordinate lookup.

## Search names, then confirm a code

```ts
import { findDistrictsByName, findPalikasByName } from 'nepali-toolkit/admin';

findDistrictsByName('kathmandu', { script: 'en', limit: 5 });
findPalikasByName('Kathmandu', { script: 'en', limit: 5 });
```

Search matches part of an English or Nepali name after normalizing case and whitespace. It does not transliterate or recognize alternative spellings. Results follow table order and default to a limit of 25. Save the selected record's code. If you add aliases, map each one to that code.

## Derive the palika or ward postal code

```ts
import { getPostalCode, getWardPostalCode, parsePostalCode } from 'nepali-toolkit/admin/postal';

getPostalCode('30608'); // '30608'
getWardPostalCode('30608', 12); // '3060812'
parsePostalCode('3060812')?.kind; // 'ward'
```

These helpers implement the GPO palika/ward scheme: five-digit palika code, then optional zero-padded two-digit ward. They do not provide a legacy post-office-code directory such as Kathmandu `44600`. Ask which scheme an external form expects before copying a derived value into it.
